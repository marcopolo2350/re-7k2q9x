# Rose's EATS: data and storage reference

Baseline tag: `v1.0-culinary-baseline` (commit 584fd51). Static site on GitHub Pages; no server, no accounts.

## Recipe object at runtime (`RECIPES`, `RID[id]`)
`{id, n name, c category, e emoji, t minutes, df difficulty, cz cozy 1-10, s serves, d description, i:[{q,u,item,note}], st:[steps], cu cuisine, img, keys:[pantry keys], mn:[main-ingredient tags], ilv:[importance per ingredient], imp:{key: importance}, cf: CHEF entry}`

## `CHEF[id]` (ingredient intelligence, v2)
Importance and substitutability are separate properties.
- `lv`: one letter per ingredient: `E` essential, `R` recommended, `O` optional. (v1 had `S` "substitutable"; it was migrated to `E` with its substitution kept, because those ingredients were defined as not skippable.)
- `rl`: one letter per ingredient, functional role: P protein, B base/starch, V vegetable/fruit, S structure, L leavening, T thickener/binder, M liquid, F fat, A acid, W sweetener, X flavor/aromatic, Z seasoning, G garnish, K preservation/cure, C color.
- `w`: `{index: omission impact / why it matters}`; omission is acceptable for R and O, not for E.
- `sub`: `{index: {x: replacement with quantity, d: substitution impact and conditions, k: [pantry keys the swap needs], wn?: allergen or usage warning}}`; any importance level can have a substitution.
- `tips`: `[{t: tip, s: step index or -1}]`.
- Personal recipes store notes per ingredient line in `S.mine[n].chef = {ing: {"<line>": {L, w, x, d, k}}, tips: [..]}`; unrated ingredients show "Not rated".

## `GUIDE[id]`
`{store: {fridge, freeze, reheat, ahead}, done, expect, mistakes: [..], rescue: {problemKey: {f: fix, ok: false when it can't be fixed safely}}, safety?}`. Problem keys: salty, spicy, watery, thick, bland, sweet, sour, dry, separated, mushy, undercooked, burnt, norise, greasy, lumpy, soggy.

## User data: `localStorage["roses-eats-v1"]` (object `S`)
`v, mine, left, log, soon, timers [{uid,label,end,mins,fired,p,left}], fav, cooked, basket {id: servings}, pantry, plan {date: [{uid,id,s,m}]}, checked, extras, tk, rating, notes, hidden, photos, gone, myIng, thr, maxMiss, gmode, hidePantry, night, week, flex, skipOpt, offline {id: {b bytes, at}}, cookSess {id,i,s,done,at}, timeline {...}`.
`load()` merges saved data over `fresh()` defaults, so new keys never erase old ones. The passcode gate uses its own key and is untouched.

## Caches (Cache API, via `sw.js`)
- `shell-<hash>`: app files; replaced on each deploy (old ones deleted on activate). Network-first, so a new deploy is used on the next load when online.
- `imgs-v1`: photos you have viewed (local images only).
- `offline-v1`: photos saved with "Save offline" (local and TheMealDB). Never deleted by updates.

## Regression baseline
Open the app with `?selftest=1` (add `&images=1` to check every photo URL). It snapshots and restores your saved data and lists pass/fail for data integrity, rendering, filters and counts, pantry tiers, grocery groups, scaling, timers, timelines and the service worker.

## Photo provenance
`photo-manifest.json`: one entry per recipe photo with recipe id, local file, SHA-256, source URL/page, creator, license, attribution requirement and verification status.
